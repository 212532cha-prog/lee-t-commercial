# LEE T 仓库 · RuoYi-Vue3 管理后台

库存操作支持扫码枪 Enter 连续计数、名称/编号搜索、手动增减、服务器草稿、相机单次解码及提交结果核验。提交前由服务器核对库存，负库存须两次确认；并发库存或草稿变化会拒绝旧版本提交。未确认请求保留原编号，登录过期后仍可核验；恢复备份会阻止恢复前请求再次入账。确认提交后的草稿刷新失败不会把库存成功误报为未知结果。原仓库工作区同步使用提交前核对及负库存二次确认。`scripts/test-ruoyi-stock.mjs` 覆盖实际接口、响应丢失、会话过期、存储故障和真实备份恢复；相机用连续测试帧验证真实 QR 解码，物理相机仍待现场验收。

产品详情支持服务端校验的照片上传/移除、原 QR 下载及单张打印；列表支持最多 50 张 QR 批量打印。Excel 导入提供真实模板、类别选择、逐行预览及确认，默认库存为 0。预览令牌绑定文件、类别与管理员会话；提交结果不确定时必须重新预览，重复名称保护防止再次新增。`scripts/test-ruoyi-product-assets.mjs` 验证实际图片、解码下载 QR、单张/批量打印、模板内容及丢失导入响应后的防重复流程。

备份模块支持完整备份下载、双路径设置版本检查、手动备份、上传校验、最后有效副本保护、维护模式及双重确认整套恢复。恢复结果不确定时锁住恢复按钮并提示先重新登录核对，成功恢复会要求重新登录。后台轮询服务器限制状态，维护或备份空间不足时仅保留备份模块；新备份成功后解锁。`scripts/test-ruoyi-backups.mjs` 覆盖实际文件、空间故障、导航限制、中断恢复请求、现场保全和恢复后库存。

管理员个人资料支持版本校验姓名编辑、JPG/PNG 头像上传/移除和密码修改。头像经服务端验证处理；密码不进入浏览器存储，修改成功撤销全部管理员旧会话并回到登录。`scripts/test-ruoyi-profile.mjs` 验证构建页面、实际图片解码、并发姓名冲突、错误密码处理、会话撤销及重新登录；API 回归见 `tests/ruoyi-profile.test.mjs`。

导出模块支持 Excel/PDF、库存/历史/盘点报告/成本、多字段、类别、位置、商品和 GMT+8 日期筛选，并显示生成进度、暂存有效期与下载入口。盘点报告可直接进入指定报告导出，回收站报告携带明确范围；返回通用导出后清除指定报告条件。过期或被相关数据变更作废的文件不能继续下载，可重新生成。`scripts/test-ruoyi-exports.mjs` 下载真实 Excel/PDF 并独立解析内容，同时校验库存不变。

管理后台提供独立登录/退出、英文优先的左侧导航，以及统一蓝灰配色、卡片、表格和响应式布局。管理员可直接打开 `/admin/` 登录；员工账号不能进入管理工作区。

成本页支持分页查看当前数量、单个成本与库存成本，金额以十进制文本格式化，保留负数及完整精度。总览的负库存提醒支持标为已读，使用服务器提醒令牌拒绝把后续新一轮负库存错误标为已读。`scripts/test-ruoyi-costs.mjs` 覆盖构建后的分页、金额、提醒变化和员工隔离，`tests/ruoyi-costs.test.mjs` 覆盖 API、101 项分页和精确金额。

盘点管理支持固定范围发布、范围查看、独立重发、取消和删除任务，以及报告差异查看、回收站、恢复和双重确认永久删除。已发布范围不随新增商品改变，盘点报告操作不调整库存。`scripts/test-ruoyi-count.mjs` 验证构建页面的完整流程、直接登录和员工越权拒绝，`tests/ruoyi-count.test.mjs` 验证真实 API、幂等提交及库存保持。

当前候选接入英文优先的仓库总览、产品管理、基础资料、员工/设备及库存历史管理。类别、供应商和仓库位置支持新增、版本校验编辑和双重确认删除；位置显示完整路径，并由接口拒绝循环引用和内置位置修改/删除。产品管理支持类别/位置筛选、分页、详情、新增、编辑、供应商及默认供应商和双重确认永久删除，继续使用现有仓库 API。若依 Vue3 工程负责构建管理页面。现有 Node.js 服务和 PostgreSQL 继续处理数据、会话、权限、备份和 Android 配对。管理前端与仓库 API 使用同一 HTTPS origin，沿用 LEE T 的 HttpOnly 会话。

## 构建与预发布

1. 在可访问 GitHub 和 npm 的 Linux 构建机运行 `bash integrations/ruoyi-vue3/build.sh /absolute/new/ruoyi-admin`。脚本锁定官方上游源码提交，应用仓库入口和页面后构建静态文件。上游没有 npm 锁文件，传递依赖由 npm 解析；库存相机的 jsQR 锁定 1.4.0，并随构建保留其许可证。
2. 把构建目录复制到隔离的 Windows 测试实例，例如 `D:\LeeT\ruoyi-admin`。通过仓库服务的保护配置将 `Environment.LEE_T_RUOYI_ADMIN_DIR` 指向该绝对路径，然后重启测试服务。管理员在同一仓库地址打开 `/admin/` 直接登录。仓库程序自身负责静态文件和 API，Windows 客户端不需要另装若依 Java 服务。
3. 从已验证的备份恢复样本，核对库存总量、总成本、负库存和补货提醒。用管理员、员工、未登录三种状态验收，然后回归原后台、扫码、盘点和断线重连。需要回退时移除该配置并重启测试服务。
4. 各模块须先完成构建页面和真实接口验收，再进入下一阶段。写操作继续通过仓库 API 的 CSRF、权限和业务校验。

员工管理支持新增、版本校验编辑、停用和密码重设，设备管理支持短效配对 QR、强制登出及解绑。配对图像只使用临时 Blob URL，关闭/过期/离开页面时清理；员工密码不写入浏览器存储。scripts/test-ruoyi-team.mjs 使用构建后的真实页面和二维码图像解码验证设备绑定及会话撤销。

库存历史从产品详情进入，支持事件类型、日期、排序和分页筛选，使用服务器时间显示 168 小时保护期；管理员可更正适用记录或双重确认设置当前数量。数量设置沿用独立版本检查与库存锚点，未知结果不会自动重发。scripts/test-ruoyi-inventory.mjs 验证响应丢失重试、并发库存变化、历史更正和保护规则。历史清理界面仍待接入。

管理写入每次从现有会话读取 CSRF，保留 metadata 版本冲突检查、库存不变规则和近期历史/盘点删除保护。已构建界面通过 scripts/test-ruoyi-products.mjs 配合隔离 PostgreSQL 测试库验证。历史清理界面仍使用原仓库入口，继续接入若依。Windows 安装器默认入口继续保持已有仓库工作区，若依候选须单独预发布验收后接入。
