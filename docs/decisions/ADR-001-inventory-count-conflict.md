# ADR-001：盘点并发冲突采用整份原子拒绝

- 状态：已确认
- 确认人：产品负责人（对话确认）
- 日期：2026-10-31
- 选择：A

## 业务规则

1. 盘点草稿记录每个产品的起始系统库存、库存版本和员工填写的实际数量。
2. 员工提交整份盘点时，服务端在同一个数据库事务内锁定并检查全部相关产品的库存版本。
3. 只要有任一产品版本与草稿记录不一致，**整份盘点拒绝提交**：不更新任何产品库存、不创建已提交盘点报告、不部分成功。
4. 返回所有冲突产品的名称、编号、草稿版本、当前库存及当前版本，提示员工刷新并重新确认实际数量；保留草稿中已填写的数据，不擅自覆盖。
5. 员工逐项确认冲突产品后重新提交整份盘点；服务端再次对全部产品执行版本检查。
6. 全部版本一致时，在同一事务内写入所有盘点库存调整、历史记录、库存版本递增及完整盘点报告；任一步骤失败则全部回滚。
7. 并发控制须防止检查后到写入前的竞态；不允许通过关闭版本检查绕过冲突。

## 验收场景

- 无冲突的多产品盘点：整份提交成功，库存及报告一致。
- 两名员工操作同一产品：在草稿创建后其他员工入/出库导致版本改变，整份提交返回冲突且所有产品库存不变。
- 冲突后刷新确认：保留原草稿，重新确认并成功提交。
- 人为注入事务中途失败：无部分库存修改、无部分报告。
- 同时提交两份基于同一库存版本的盘点：最多一份成功，另一份冲突拒绝。
