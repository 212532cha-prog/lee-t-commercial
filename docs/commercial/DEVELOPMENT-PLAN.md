## 当前基线

初次 HTTPS 激活、离线许可证导入和启动校验已实现。付费升级及换机的授权审批、签发与兑换已有 PostgreSQL 实现，审批目前通过发行方命令行进行。员工网页一次性二维码配对、强制登出、解绑和旧仓库备份兼容已实现。

基线在 PostgreSQL 17.11 上分别用 Node.js 22 和 24 跑完 238 项测试，两轮均为 0 失败、0 跳过。此记录对应基线提交。正式发布仍需完整的商业模块和实机验收。

## 每阶段执行规则

1. 先写清验收用例和失败场景，再实现功能并运行专项测试。测试失败先定位和修复，再重跑本阶段。
2. 每个阶段运行原仓库回归和对应的商业版测试。最终候选版本在 Node.js 22/24、原生 PostgreSQL 17、适用的 Windows runner 及真实设备上按清单复验。不得删除、跳过或弱化断言。CI 或浏览器模拟不能替代真实安装、手机相机和仓库局域网验收。
3. 保留版本、提交 SHA、环境、测试命令、通过/失败/跳过数量和现场证据。每项只标为通过、失败、未执行或阻塞，并记录原因与复测条件。
4. 正式发布前使用同一个候选版本完成干净安装、激活、断网重启、扫码、升级、备份恢复及新服务器换机。任何必需项未通过时继续保持候选版状态。
