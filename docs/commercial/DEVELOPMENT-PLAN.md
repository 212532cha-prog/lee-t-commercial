## 3. 验收执行规则

1. 每阶段先定义正常、失败、越权、并发和恢复用例，再完成实现与专项测试。任一测试失败先定位并修复，重跑通过才进入下一阶段。禁止删除测试、跳过或降低断言。
2. 每阶段执行对应商业测试及原仓库回归。最终候选在 Node.js 22/24、原生 PostgreSQL 17、适用 Windows runner、真实设备和目标网络上全量复跑。
3. 每条证据记录需求号、提交 SHA、安装包版本或校验值、环境与数据规模、测试步骤/命令、通过/失败/跳过数、时间及实际结果。状态只用通过、失败、未执行或阻塞。模拟测试不能替代真实安装、摄像头、局域网或备份恢复。
4. 现场验收使用隔离测试仓库或已验证备份的测试副本。涉及升级、卸载或恢复前保全数据。部署和回退需明确验证版本、服务状态和业务数据。
