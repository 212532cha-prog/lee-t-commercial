# LEE T License Center standalone installation

Download `LEE-T-License-Center-Setup.exe` on Windows 10/11 x64 and run it as an administrator. No warehouse installation, Node.js, PostgreSQL download, source checkout, terminal or internet activation is required. On first installation choose an issuer password of 12–128 characters. The desktop shortcut opens the offline signing window.

The installation has its own Node.js, PostgreSQL 17, desktop .NET runtime, Microsoft Visual C++ redistributable and offline signing backend. It uses `LeeTLicensePostgreSQL17` on loopback port 55435 and `LeeTLicenseCenter` on loopback HTTPS port 8444. Both start automatically with Windows; SCM starts the database before the backend and restarts crashed services. Client certificates and the issuer password remain required. An elevated desktop can restart stopped issuer services when connecting.

Program: `C:\Program Files\LEE T License Center`. Private ledger, signing key and TLS configuration: `C:\ProgramData\Lee T License Center`. A reinstall preserves the issuer key and ledger. When adopting the previous local issuer, setup verifies the dedicated cluster path before rebinding only its database service to the standalone runtime. It never changes `LeeTPostgreSQL17` or warehouse data. Keep a backup before removing old test installations.

Uninstall through Windows Settings → Apps → LEE T License Center → Uninstall. Choose whether to retain issuer records and keys or permanently delete them. Deleting keys prevents further signing with that identity; already distributed customers still trust the original public key. Silent uninstall keeps data unless explicitly passed `/DeleteIssuerData=1`. An unattended install accepts `/IssuerPasswordFile="absolute protected password file path"`; remove that file afterwards. Never put an actual password on the command line.

The release workflow tests the compiled installer on a clean Windows runner: initialization, TLS password authentication and refusal of a wrong password, customer and payment creation, offline signing and independent Ed25519 verification, exact signing retry, cold service start, crash recovery, repair, retained-data reinstall, and full removal. All Linux tests run against PostgreSQL 17 before Windows packaging. A CI pass is not evidence of a physical PC reboot or code signing. Authenticode publisher signing and actual customer-PC acceptance remain release gates; unsigned builds must not be advertised as signed production releases.
