# Windows 安装、运行、更新与换机

REQ-20261101；候选版本0.8.5。现场验收完成前不得把工程测试通过当作正式上线许可。

## 准备服务器

1. 使用受支持的64位Windows、Node.js 24 LTS、原生PostgreSQL 17及.NET Framework 4.x。管理员PowerShell执行安装。应用运行不需要Python、OpenSSL、Docker或WSL；开发测试另有依赖。
2. 应用目录至少1GB空闲，数据盘至少2GB空闲，另外预留数据库、照片和备份增长空间。不能在空间已满的C盘强行安装。路径可选其他盘，数据目录放在应用目录外。备份使用两个不同的专用子目录，路径2可为外接盘，固定其盘符；不要直接选磁盘根目录或共享其他业务资料的目录。
3. 为服务器在路由器保留IPv4地址，确认连接的是仓库受信任的Private网络。安装器仅开放该接口、Private配置和本地子网的HTTPS端口，不做公网转发。
4. 安装专用PostgreSQL 17实例，监听仅为localhost，使用SCRAM密码验证。通过本机pgAdmin的角色/数据库界面创建专用LOGIN角色和由它拥有的空数据库；角色不能拥有超级用户、创建角色、复制或绕过RLS权限。应用角色需要在自己数据库的public schema执行建表/迁移。不要让应用使用postgres管理账户。记录实例服务名；安装器不会改动现有数据库服务器的监听规则或初始化其他业务库。
5. 若Node.js只安装在个人账户不可访问的位置，先改为所有用户可读取的安装路径。服务账户为LocalService，应用目录只读，数据及指定备份目录可写；外接盘必须支持这些权限（推荐NTFS）。网络共享需要另外配置服务身份，当前安装器按本地/外接盘设计。

## 首次安装

解压候选源代码到固定应用目录；首次生产依赖安装需要网络。进入目录，在管理员PowerShell运行：

```powershell
.\scripts\windows\Install-Warehouse.ps1 -DataDir 'D:\WarehouseData' -BackupPath1 'D:\WarehouseBackups' -BackupPath2 'E:\WarehouseBackups' -Address '<本机实际IPv4>' -PostgresService '<专用PostgreSQL服务名>'
```

路径和地址均为示例，必须替换。按组织策略审核/签名脚本，不永久降低系统执行策略。安装器交互读取数据库连接URL和约定的初始管理员口令，输入不回显；不要把真实口令写在命令行、截图、聊天或Git中。管理员用户名为CTL LEE；已有数据库不会重置其身份或口令。安装失败不要删除数据目录重装，先检查错误。

安装器生成服务器专用CA和含所选IP的HTTPS证书，敏感配置写入受限数据目录service.private.json。公开根证书warehouse-root-ca.cer可给客户端安装；PFX、其口令、数据库连接和私有配置不得给员工或提交代码。服务器证书有效期一年，需在到期前安排签发替换和验证。手机安装并信任根证书后访问安装器输出的HTTPS地址；仍出现警告就停止处理证书配置，不跳过警告。应用的首屏是登录页，无公开注册。

## 日常启动、关闭与排错

服务名TatLeeWarehouse，依赖指定PostgreSQL服务并自动启动。正常停机先停止应用服务，再关闭Windows；再次开机保留账号、库存、历史和草稿。重启后的未完成盘点必须重新计数，提交过的报告保留。员工断线或刷新也不恢复未提交数量。

```powershell
Get-Service TatLeeWarehouse
Stop-Service TatLeeWarehouse
Start-Service TatLeeWarehouse
```

服务日志在数据目录warehouse-service.log，超过约2MB轮换一份。日志与私有配置仅管理员查看。服务意外退出由SCM有限重试；不能反复忽略数据库或恢复错误。备份失败看备份模块；只有同次两条路径均确认空间满才限制管理员，员工继续业务，管理员成功生成并校验新备份后解除限制。

## 下载备份并换电脑

1. 旧机管理员进入备份模块，点击「下载完整备份」，取得通过校验的 .whb 文件，无需先配置自动备份目录。检查时间和大小，把文件安全放到可带到新机的介质；下载不等于已经恢复成功。正式切换前停止员工写入，在维护模式生成最后备份，避免切换后漏掉旧机新增资料。
2. 新机安装同版本应用、Node.js和PostgreSQL，建立专用空数据库，按新机地址运行安装器。需要自动备份时，可同时传入两个备份路径；仅使用手动下载时可省略两项。数据恢复包不包含新机数据库连接密码、TLS私钥、Windows服务或应用程序本身，因此不能只把备份双击运行。
3. 新机管理员进入备份模块，上传旧.whb，校验成功后执行整个系统恢复并确认。系统先保留新机恢复前现场，再恢复数据库及照片，保留新机配置的备份路径并撤销旧会话。恢复后用备份里的旧管理员账号/口令登录。
4. 对照旧机核对产品、实际库存、员工、历史、报告、照片和草稿；提交一笔测试入库/出库及只生成报告的盘点，确认下载可用。已启用自动备份时，也要确认备份路径1/2可写。恢复不把盘点报告数量写入库存。新机再次制作并校验完整备份。
5. 客户端改访问新机HTTPS地址，信任新机根证书；产品QR保存稳定产品标识，无需因IP更改重印。扫码枪按HID键盘模式连接使用它的电脑/手机，设为一次扫描发送一个Enter，聚焦扫码框；三次同码应为3，−/＋可调。实际枪型及手机配对需现场验证。
6. 确认新机完整工作后停止旧机服务。只保留一台权威服务器，避免两边各自写入形成两个不同库存。保留旧机最后有效备份和恢复前现场直到核对完成。

换机不绑定指定电脑，但还需要程序、数据库、证书和权限配置；不是仅修改旧机页面中的IP就把服务器移动过去。

## Cloudflare Tunnel 入口

使用既有 HTTPS Tunnel 时，保留本机 `PUBLIC_ORIGIN` 与监听端口，在受保护配置的 `Environment` 另设 `TUNNEL_PUBLIC_ORIGIN`，值为该安装已配置的完整 HTTPS 域名，不带末尾斜杠。核对 Tunnel 使用正确的 CA 验证本机证书，并分别从局域网和域名测试登录。仅配置域名不会创建 Tunnel。

## 更新与回退

先进入维护模式，制作并下载校验通过的完整备份，保存当前程序版本。停止应用服务，安装新版本到独立目录，安装生产依赖，保持原数据目录和受限配置；确认服务AppRoot/入口指向新版本并重新构建服务宿主。不要覆盖或清空原数据。启动后迁移校验、核对关键功能及新备份再开放写入。

不支持在未知新结构上直接降级程序。回退要停止写入，保存当前现场，使用与备份结构匹配的旧程序和专用恢复环境恢复升级前备份，核对后再切回。较新备份或结构不匹配时系统拒绝导入，不能关闭该校验。

## 必须留存的现场证据

Windows安装/服务自启与关机重启；iPhone/Android无证书警告的摄像头实际解码；真实HID扫码累加；断外网仍可局域网工作、断LAN提示及重新盘点；外接盘断开/写满与双满限制；旧机备份到新机恢复。记录版本、设备/系统/浏览器、时间、结果及必要截图，不保存口令或生产资料到仓库。具体117个验收案例见根目录验收清单，未执行不得标通过。

## 批量打印产品二维码

管理员在「产品」列表勾选要打印的产品，每批最多 50 个，点击「批量打印 QR」。浏览器会打开标签页及打印对话框，可选择打印机或另存为 PDF。每张标签含产品编号、名称和现有产品二维码。可加载更多产品后继续勾选，重新筛选会清空勾选。正式贴标前先试印一张，用仓库扫码流程核对对应产品。

## 从 Excel 新增产品

管理员在「产品」选择「导入 Excel」，下载模板。保留 Products 工作表名称和第一行表头，填写名称、单件成本（RM，最多两位小数）和最低库存（非负整数）。如从其他表复制数据，请粘贴为值。每次最多 200 行、1 MB。

选一个已有类别，上传 .xlsx 后点击「预览」。修正显示的行号和错误后重新预览，再确认导入。同一类别已有同名产品或同批重名时会阻止整批导入，名称比较忽略大小写。新产品由系统生成编号和二维码，位置设为未分配，库存为 0。导入后可用批量二维码打印；需要设置位置、供应商或调整实际库存时，通过对应产品与库存功能处理。

### LEE T Commercial · 手机免装仓库 CA

先为仓库预留 LAN IPv4，并准备一个自有域名的子域名。仓库 Wi-Fi 上的 DNS 必须把该主机名解析到这个 IPv4。可以用 DNS-01 验证签发公开受信任的证书，服务器继续只接受局域网连接。准备含私钥和中间证书链的 PFX，保留其密码，并安排续期。当前脚本验证和应用 PFX，证书签发和续期由部署方处理。

这是部署人员选用公开证书时的配置。新装时可使用 PowerShell 安装脚本的 `-HttpsHostname` 和 `-HttpsPfxPath` 参数，密码在安装窗口输入。已有安装可先下载完整业务备份，再用管理员 PowerShell 运行 `Set-CommercialLanHttps.ps1`，传入现有服务的 `-ConfigPath`、预留的 `-Address`、`-HttpsHostname` 和 `-HttpsPfxPath`。它会预检 DNS 和证书，重启应用服务，并在新地址无法验证原仓库身份时恢复原配置。续期时可用同一脚本替换 PFX。

使用新的 HTTPS 主机名打开后台，必要时解除测试员工的旧设备绑定并重新生成配对码。正式验收使用从未装过仓库 CA 的手机，在同一 Wi-Fi 扫码、登录、入库、出库、盘点。

标准测试安装器自动选择 Windows 网络地址。如果当前唯一合适的网络为公用网络，安装窗口会要求确认是否信任该网络，并仅在确认后将其设为专用网络。员工配对码可携带服务器证书指纹，Android 配对探测会核对指纹和仓库身份。带指纹的配对码使用 APK 内置员工页面，登录、入库、出库和盘点请求由 App 原生连接核对证书指纹。旧配对码保留系统证书连接流程。免装 CA 的完整业务流程仍待 Android 真机验收。
